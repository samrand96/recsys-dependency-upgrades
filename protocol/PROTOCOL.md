# Phase 1 feasibility pilot protocol v0

**Approved by the researcher on 12 November 2026.** The `protocol-v0` tag freezes the approved protocol and its referenced manifests before any upgrade outcome is inspected. All pilot transitions are development cases.

## Dataset and split

Use [MovieLens 1M](https://grouplens.org/datasets/movielens/1m/) from GroupLens. Run `uv run --locked python data/prepare_ml1m.py` in the pinned orchestrator environment. The script verifies the publisher's MD5 and the pinned archive SHA-256, builds the prepared arrays once, and records the output SHA-256, cutoffs and counts in `data/manifest.json`. Keep the downloaded ZIP and prepared arrays local under the [GroupLens research-use terms](https://files.grouplens.org/datasets/movielens/ml-1m-README.txt).

Read all valid rating events. Stop on missing or malformed fields. For each duplicate `(user, item)` pair, retain the earliest observation, breaking equal-time ties by source order. MovieLens 1M has zero duplicate pairs under this rule. Sort by integer Unix timestamp, preserving source order within a second. At each nominal cumulative percentile `p`, use the timestamp of the event at zero-based index `floor(n × p / 100)` as the boundary. Put all events at the boundary in the later interval. The training catalogue and user/item mappings contain only IDs observed in training. No k-core or future-based filtering precedes the split.

The default 80/10/10 split gives 992 warm test users. Moving the cut points to 70/10/20 gives 956. A data-only sweep over whole-percent training shares from 10% to 85%, with 10% nominal validation, found the most support at 76/10/14, with **1,007 warm test users**. The sweep breaks count ties in favor of the larger training share. The exact upper bound is 1,166 over all global timestamp cutoffs even with zero validation gap. A user contributes to this bound when a relevant test event lies at or after the cutoff and both the user and that event's item were first observed before it. This makes the planned target of 1,500 infeasible with the global split and frozen training catalogue. The selected **76/10/14** split keeps 397 warm validation users for baseline tuning. The first validation and test timestamps are respectively `975351119` and `976661178`. This choice used dataset counts only.

Use `ml1m.npz` for fixed-data inference and retraining. `train`, `validation` and `test` contain `int64` user index, item index and rating triples in chronological order, with cold rows removed from validation and test. `user_ids` and `item_ids` map zero-based indices to ascending external IDs. The manifest reports cold users and items, excluded interactions, relevant interactions lost to eligibility, and the counts at tied boundary timestamps. Cold-user and cold-item exclusions can overlap. `test_users` enumerates the primary evaluation population.

As a sensitivity analysis, use a separate chronological split within each user with nominal 70/10/20 proportions, keeping timestamp ties together using the same boundary rule. Derive its mappings, candidates and activity groups from its own training partition. This split can train on one user's events after another user's test cutoff. Report its results separately from the global split.

## Relevance, candidate eligibility and ranking

- An event with rating ≥4 provides binary relevance. Test candidates are all items in the training catalogue after excluding every item the user interacted with in training or validation, at any rating. For validation, use the training catalogue and mask training interactions only. Use all eligible candidates for evaluation.
- Score users with at least one training event and at least one eligible relevant event in the evaluated split. Count users excluded by cold start, missing eligible relevance, and item-catalogue eligibility. Fix the scoring population and candidate universe across sides. Log candidate retrieval separately if the model retrieves only a subset of the eligible universe.
- Rank by the implementation's native output for primary quality. Also compute a diagnostic canonical ranking in the orchestrator over the full eligible score vector, descending by score with ascending external item ID for exact ties. Retain all boundary-tied items before selection, or use full lexicographic ranking. Map internal IDs to external IDs for canonical tie-breaking and use a common ID space for every metric and contract comparison. Report the number of users with a tie crossing K and the tie sizes. Near ties have no primary tolerance.
- Require unique items, valid training item IDs, no seen items, and finite scores for returned items and unmasked scores used for canonical ranking. Require exactly `min(K, eligible candidate count)` returned items. A contract violation takes precedence over quality verdicts. Keep invalid output and its evidence in the ledger.

## Outcomes and statistical rules

- Use binary NDCG@10 as the primary quality measure, Recall@10 and NDCG@20 as secondary measures. NDCG uses `1/log2(rank + 1)` with rank starting at 1, normalized by the ideal ordering of eligible relevant items up to K. Recall divides hits by all eligible relevant items for that user. Report behavioral overlap@10 (intersection size divided by `min(10, eligible count)`), the fraction of users whose list changes, shared-item position changes, and exact ties at K. Report maximum absolute score difference and the relative L2 norm on aligned unmasked eligible scores as diagnostics. If the old score vector has zero norm, report zero for identical vectors and leave the ratio undefined otherwise.
- Fix low, medium and high activity groups from training interaction counts across all training users. Use nearest-rank 1/3 and 2/3 quantiles as inclusive upper bounds for the low and medium groups. Equal counts share a group. The selected split yields cutoffs 51 and 140, and group sizes 223, 277 and 507 among eligible test users. Report group estimates and sizes. For group-level claims within a case and mode, use Bonferroni-adjusted two-sided intervals at `1 − 0.05/3` per group.
- For each user and paired seed, define loss as old minus new NDCG@10. Average equally across eligible users and paired seeds. Report two-sided 95% intervals and all absolute tolerances δ in `{0.002, 0.005, 0.010}`. For each δ, report `contract_failure` for a contract violation, `harmful` when the lower bound exceeds δ, `improved` when the upper bound is below −δ, `equivalent` when the interval lies entirely in `[−δ, δ]`, and `inconclusive` otherwise. Keep installation/runtime failures, behavioral changes, quality regressions, contract violations and uncertain results distinct.
- For deterministic inference, resample paired users with replacement using 10,000 bootstrap replicates and take percentile endpoints. For retraining, use a paired t interval on the five seed-level mean differences as the primary interval. As a sensitivity check, resample paired seeds, then users, for 10,000 replicates. Within each replicate use the same user draw across sampled seeds to preserve user pairing across models. Report the resampling unit for each interval. Use the pinned orchestrator's `PCG64` with analysis seed `713`.
